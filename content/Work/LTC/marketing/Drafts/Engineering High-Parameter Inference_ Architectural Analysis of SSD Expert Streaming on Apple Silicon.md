### Engineering High-Parameter Inference: Architectural Analysis of SSD Expert Streaming on Apple Silicon

##### 1\. Executive Introduction: Breaking the Unified Memory Barrier

The evolution of Large Language Models (LLMs) has reached a physical impasse where model scale—often exceeding 100 billion parameters—surpasses the unified memory capacity of even high-end prosumer hardware. For Apple Silicon, the "memory wall" typically forces 100B+ models into slow virtual memory swapping or outright execution failure. Out-of-core execution represents a strategic paradigm shift; rather than being bound by RAM, the SwiftLM architecture treats the high-speed NVMe SSD as an active tier of the memory hierarchy. This allows for the execution of massive Mixture of Experts (MoE) models, such as the 209GB Qwen3.5-397B, by streaming parameters on demand. This approach democratizes frontier-scale inference for local, private environments previously reserved for datacenter clusters.The primary objective of this report is to detail the engineering principles of SwiftLM that enable massive MoE models to run on memory-constrained Apple Silicon. The architecture is built upon four technical pillars:

* **Native Swift/Metal Runtime:**  A zero-Python environment that eliminates the Global Interpreter Lock (GIL) and redundant memory copies.  
* **SSD Expert Streaming:**  A high-performance I/O pipeline that loads MoE weights directly from NVMe to GPU.  
* **TurboQuant KV Compression:**  A hybrid quantization framework reducing memory footprints for long-context (100K+) inference.  
* **Async-Eval Pipeline:**  A temporal orchestration layer that overlaps compute with speculative I/O pre-loading.By transitioning to a Python-less runtime, SwiftLM gains the low-level deterministic control required for extreme hardware orchestration.

##### 2\. The Native Inference Paradigm: Bypassing the Python Tax

The strategic decision to eliminate the Python runtime is rooted in the need for precise memory management and low-latency execution. Standard frameworks suffer from the "Python tax"—latency introduced by the Global Interpreter Lock (GIL) and the overhead of managed memory objects. By stripping these layers, SwiftLM achieves a deterministic execution path where multi-threaded concurrency is no longer serialized by a central interpreter lock, allowing for the sub-millisecond synchronization required for SSD-to-GPU data transfers.Execute a single-binary strategy to bypass runtime abstractions and achieve "Bare-Metal" performance. This native foundation provides the low-level orchestration capabilities necessary to manage the I/O-compute synchronization that enables out-of-core execution.

##### 3\. Architectural Deep-Dive: SSD Expert Streaming & I/O Optimization

For models exceeding 200GB like Qwen3.5-397B, SSD streaming is a strategic necessity to bypass physical RAM limits. SwiftLM implements a rewritten streaming pipeline designed to saturate the NVMe interface while maintaining a stable resident memory footprint.The system utilizes  **Concurrent NVMe pread (QD=24)**  to maximize I/O throughput. By employing DispatchQueue.concurrentPerform, the engine saturates the NVMe controller queue depth across 24 parallel reads (8 experts x 3 projections: gate, up, and down). To further optimize the pipeline, SwiftLM implements the  **needsMoeFlush**  gate. This prevents the per-layer GPU sync barrier from firing unconditionally—a critical fix that previously flushed the kernel-batching pipeline and regressed performance in standard MLX implementations.Architectural analysis reveals that at steady state,  **GPU compute is the actual bottleneck (\~190ms of \~200ms per-token time)** . This is because the OS page cache effectively serves approximately 90% of expert reads from RAM. Crucially, we discovered that implementing application-level LRU caches for experts actually regressed performance (4.84 to 4.01 tok/s) by "stealing" memory from the OS page cache. SwiftLM therefore delegates cache management to the kernel. To further reduce orchestration,  **Cross-Projection Batching**  collapses \~1,400 per-expert calls into \~48 per-token calls via SwitchGLU, while  **Persistent Metal Buffers**  eliminate per-token allocation latency by reusing expert buffers once per layer.

##### 4\. The Async-Eval Pipeline and Speculative Pre-loading

Maintaining stable tokens-per-second (TPS) requires the effective overlapping of compute and I/O. The  **AsyncEval Pipeline**  achieves this by utilizing previous-token routing data to speculatively pre-load the experts required for the next token. This speculative pre-loading achieves a 70% hit rate, transforming SSD latency into a background process.For hybrid architectures like Qwen3.5, which combine Attention and Mamba layers, the engine implements  **MambaCache checkpointing and rollback** . Unlike standard attention KV caches that allow for simple offset decrements, Mamba’s recurrent state integrates the entire history. This implementation ensures that speculative decoding can safely "roll back" the recurrent state during rejection sampling without corrupting the model's temporal context.Users can manage the quality-speed tradeoff via  **Runtime Top-K Expert Selection**  (SWIFTLM\_TOP\_K). By reducing active experts per token at runtime, the system can achieve significant throughput gains (up to 10x) while maintaining coherent output. These optimizations ensure that NVMe bandwidth is used only where it adds the highest marginal value to the inference stream.

##### 5\. Memory Compression: TurboQuant KV Cache Optimization

In long-context scenarios, the "Memory Wall" shifts to the KV cache. SwiftLM utilizes a "Holy Grail" hybrid V2+V3  **TurboQuant**  architecture. While original V3 implementations were slow due to software dequantization, SwiftLM achieves near-lossless 3.5-bit compression by porting non-linear Lloyd-Max codebooks into a native C++ path and utilizing  **fused Metal (bggml-metal) shaders**  for dequantization.The architecture employs a mathematical divergence between K and V caches:

1. **K-Cache (4.25 bits/dim):**  Utilizes  **3-bit PolarQuant**  and a Fast Walsh-Hadamard Transform (WHT) rotation. Post-rotation, coordinates follow a  **Beta distribution** , making scalar quantization near-optimal. A 1-bit QJL (Quantized Johnson-Lindenstrauss) residual correction is added to maintain inner-product stability and attention accuracy.  
2. **V-Cache (3.125 bits/dim):**  Since the V-cache does not participate in dot-product scoring, QJL is disabled to extract an additional 25% memory saving without quality loss.This enables hardware with 24GB RAM to process 100K contexts on models like  **Gemma 4-26B** —a feat that previously required a 64GB Mac Studio—by pairing 3-bit KV compression with SSD weight streaming.

##### 6\. Bare-Metal Implementation: The "Aha\! Moment" of Embedding Scales

Implementing model architectures from scratch reveals subtle "silent failures" hidden by high-level libraries. A pivotal engineering find occurred with the Gemma architecture, which features complex interleaved local and global attention.Initial tests produced only infinite whitespace. Though structural shapes were correct, the magnitudes were flawed. The "Aha\! moment" was the discovery of a missing sqrt(hidden\_size) scale factor. With a hidden size of  **2816** , the missing scale made every activation in the network  **53x too small** . Correcting this single mathematical operation "woke" the model instantly.This highlights the necessity of "bare-metal" verification: model logit shapes may indicate structural success while the underlying magnitudes remain fundamentally broken. Precision in these low-level implementations is the cornerstone of the SwiftLM engine's stability.

##### 8\. Strategic Conclusion: The Future of Out-of-Core Inference

The convergence of native Swift execution, concurrent NVMe I/O, and advanced TurboQuant compression effectively bypasses the unified memory limits of Apple Silicon. By treating the NVMe SSD as a high-speed extension of the GPU memory hierarchy and utilizing the OS kernel for intelligent caching, we have transitioned 100B+ parameter models from "impossible" to "performant" on prosumer hardware. This represents a fundamental democratization of frontier-scale AI, enabling local and private execution of the world's most powerful architectures on the machines professionals already own.
